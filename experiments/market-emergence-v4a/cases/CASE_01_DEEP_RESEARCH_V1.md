## 1. Why this case exists

Case 01 is not a visual demo about “semiconductor stocks moving together.”

It is a test of whether TRQuant can take a common market observation:

> several semiconductor stocks rise together

and turn it into a disciplined chain:

\[
\boxed{
\text{Observation}
\rightarrow
\text{Competing Explanations}
\rightarrow
\text{Controlled Intervention}
\rightarrow
\text{Path Differences}
\rightarrow
\text{Evidence Requirements}
\rightarrow
\text{Decision Relevance}
}
\]

The case is deliberately chosen because the same surface pattern can be generated by very different mechanisms:

- broad market risk-on;
- semiconductor demand/earnings expectation revision;
- one leader repricing first and peers following later;
- ETF/portfolio/common flow;
- trend-sensitive feedback;
- lower depth / higher impact;
- residual coincidence.

The case is useful only if those explanations generate distinguishable signatures and lead to different evidence requests.

## 2. TRQuant project research that constrains the case

This dossier is grounded in the existing TRQuant project research rather than invented from the simulator UI.

### 2.1 Decision-sufficient compression, not maximum compression

The TRQuant Foundation argues that high-dimensional market data should be compressed only when decision-relevant information is preserved.

For Case 01, this means:

- do not model every semiconductor company, fund, exchange, and order;
- do not reduce the whole case to one “theme strength” scalar either;
- preserve only the distinctions that can change the explanation or the investment decision.

The minimum distinctions required here are:

\[
\boxed{
\text{Market}
+
\text{Theme}
+
\text{Stock-specific}
+
\text{Unknown}
}
\]

and:

\[
\boxed{
\text{Initiation}
+
\text{Price Formation}
+
\text{Amplification}
+
\text{Propagation}
+
\text{Liquidity}
}
\]

### 2.2 Common structure + sparse shocks + unknown

TRQuant project research explicitly separates:

- common structure affecting many assets;
- sparse/special shocks affecting a sector or company;
- unknown/noise.

Case 01 therefore must never interpret “all semiconductors rose” as one explanation by itself.

The first analytical question is:

\[
\text{How much of the move is broad common structure?}
\]

The second is:

\[
\text{What remains after market and theme common movement?}
\]

The residual is not automatically alpha or information. It may be:

- company-specific information;
- flow;
- timing/lead-lag;
- liquidity;
- noise.

### 2.3 Evidence before narrative

The TRQuant Foundation rejects the pattern:

\[
\text{price move}
\rightarrow
\text{find a matching news story}
\rightarrow
\text{declare cause}
\]

The correct Case 01 workflow is:

1. establish that the cross-sectional move is unusual enough to investigate;
2. remove broad-market/common-theme explanations where possible;
3. enumerate competing mechanisms;
4. ask what evidence each mechanism predicts;
5. preserve contradictory evidence;
6. keep UNKNOWN when evidence is insufficient.

The simulator may know the generated cause.

The real market does not.

### 2.4 Time scale separation

TRQuant project research separates fast, medium, and slow investment reasoning.

For Case 01:

- **Fast**: price discovery, order flow, liquidity, immediate event response;
- **Medium**: earnings revisions, industry strength, trend persistence, portfolio flow;
- **Slow**: AI capex, semiconductor cycle, competitive position, capital intensity, long-run value drivers.

A semiconductor theme can be structurally attractive on a slow horizon while being overextended on a fast horizon.

The case must not collapse those statements into one “bullish/bearish” state.

### 2.5 Real investment value is the gate

Existing TRQuant investment-process work is explicit that system construction is not the objective.

The objective is to improve:

- attention allocation;
- depth of industry/company understanding;
- evidence-to-belief conversion;
- decision quality;
- execution quality;
- learning from missed opportunities.

Therefore Case 01 passes only if it helps answer questions such as:

- Is this a broad market move or a semiconductor-specific change?
- Is the theme move supported by new earnings/demand expectations?
- Is price moving mainly because investors revised expectations, or because common flow is temporarily moving prices?
- Is feedback strengthening persistence?
- Is low liquidity amplifying the move?
- Which stocks deserve deeper research because they are stronger than both market and theme?
- What new evidence would falsify the current explanation?

## 3. Expectations Investing contribution

The project copy of *Expectations Investing* adds an important layer that the original Case 01 contract did not yet make explicit enough.

Stock prices reflect expectations.

Investment opportunity comes from correctly anticipating revisions in price-implied expectations, not merely identifying a good company or a strong industry.

For the semiconductor case, a generic “information shock” is too shallow.

A useful information shock should represent a revision in one or more economically meaningful expectation drivers.

### 3.1 Semiconductor expectation-trigger vector

For Case 01 v1 research, define the latent expectation vector:

\[
E_t^{semi}
=
\begin{bmatrix}
D_t \\
P_t \\
M_t \\
I_t \\
C_t
\end{bmatrix}
\]

where:

- \(D_t\): expected end demand / unit or workload growth;
- \(P_t\): expected price and mix;
- \(M_t\): expected operating leverage / margin economics;
- \(I_t\): expected investment intensity / capital required;
- \(C_t\): expected capacity / supply constraint conditions.

These are not direct real-world observables.

They are latent research variables that organize evidence.

### 3.2 Economic channels relevant to a semiconductor theme

A theme-level expectation revision can be triggered by evidence such as:

- AI/data-center capex changes;
- accelerator/server demand;
- HBM/DRAM/NAND pricing or supply;
- foundry capacity and utilization;
- advanced packaging constraints;
- semiconductor-equipment order trends;
- export controls / policy constraints;
- customer inventory;
- lead times;
- gross-margin or operating-leverage changes;
- customer concentration changes.

The first engine slice does not need to simulate all of these.

It needs to preserve the fact that “theme information” means a change in expected economics, not a magic upward price jump.

## 4. A deeper mechanism grammar

The seven competing mechanisms in the frozen Case 01 contract remain valid, but project research suggests they should not be treated as seven mutually exclusive additive buckets.

Real market moves often form a chain.

Example:

\[
\text{AI capex revision}
\rightarrow
\text{NVDA reference repricing}
\rightarrow
\text{fundamental buying}
\rightarrow
\text{price rise}
\rightarrow
\text{trend flow}
\rightarrow
\text{peer propagation}
\]

The correct grammar is therefore:

### Layer A — Initiator

What starts the move?

- \`market_beta\`
- \`theme_information\`
- \`leader_information\`
- \`common_flow\`
- \`residual_shock\`

### Layer B — Price-formation channel

How does pressure become price?

- signed flow;
- price impact;
- depth;
- spread;
- transient/permanent impact.

### Layer C — Amplifier

What increases persistence or magnitude after the initial move?

- trend feedback;
- attention-sensitive discretionary flow;
- dealer/inventory response;
- constraint-driven flow.

### Layer D — Propagation

How does a move in one asset or subgroup appear elsewhere?

- common simultaneous exposure;
- model network;
- lead-lag response;
- economic relationship;
- ETF/common holdings.

### Layer E — Environment

What changes the response of the whole system?

- market risk state;
- liquidity;
- volatility;
- participation mix.

### Layer F — Residual

What remains unexplained?

- stochastic disturbance;
- missing information;
- model misspecification;
- measurement error.

This grammar is critical because it prevents double counting.

For example, if a theme information shock causes fundamental agents to buy, the resulting flow is a transmission channel from information to price, not a second independent “cause” in the same accounting sense.

## 5. First canonical experiment: information repricing vs common flow

The frozen Case 01 contract already specifies the first A/B pair.

This dossier sharpens what those two experiments mean economically.

### Run A — Theme information repricing

Hold fixed:

- seed;
- participant population;
- network;
- initial prices;
- liquidity;
- noise;
- trend gain.

Change only:

\[
\Delta E_t^{semi} > 0
\]

The simplest v1 implementation can map that revision to a theme-level latent reference-anchor change.

Expected signatures:

- fundamental/valuation-sensitive participants respond first;
- reference anchors remain higher after the initial event;
- price path should have a larger permanent component;
- subsequent trend flow may amplify but is not the initiating mechanism;
- stopping discretionary flow should not fully reverse the move if the anchor remains changed.

### Run B — Common theme flow

Hold fixed the same initial state.

Do **not** change the reference anchors.

Inject:

\[
OFI_{i,t}>0
\quad
\forall i \in \text{theme}
\]

for a finite duration.

Expected signatures:

- prices rise immediately through impact;
- cross-sectional synchronization can be high even without changed economics;
- the path should be more sensitive to depth;
- once the flow stops, transient impact can decay;
- mean reversion / dealer response may become more visible.

### Core research question

If two scenarios produce similar terminal returns:

> Can the system still distinguish them from the path, participant mix, persistence, recovery, and evidence requirements?

If not, the simulator is not yet doing useful mechanism research.

## 6. Market -> Theme -> Stock decomposition

The existing project theory strongly supports separating common structure from special shocks.

Case 01 therefore uses three observable price layers:

\[
R_{stock}
=
R_{market}
+
(R_{theme}-R_{market})
+
(R_{stock}-R_{theme})
\]

For v1 these are descriptive comparisons, not causal factor attribution.

Define:

\[
R_M = R_{SPY}
\]

\[
R_S = \frac{1}{N}\sum_{i \in semi}R_i
\]

\[
X_{theme}=R_S-R_M
\]

\[
X_{stock}=R_i-R_S
\]

These answer:

- Did the market rise?
- Did semiconductors outperform the market?
- Did the selected stock outperform the semiconductor theme?

They do **not** answer why.

Why requires mechanism evidence.

## 7. Cross-sectional diagnostics

A professional Case 01 should not only show one selected stock.

At each analysis point, compute:

### 7.1 Theme breadth

\[
Breadth_t
=
\frac{1}{N}
\sum_i
1(R_{i,t}>0)
\]

### 7.2 Theme dispersion

\[
Dispersion_t
=
StdDev(R_{i,t})
\]

### 7.3 Common-mode share

Use the first eigenvalue share of the return correlation matrix where an adequate rolling sample exists:

\[
CommonShare
=
\frac{\lambda_1}{\operatorname{tr}(C)}
\]

Boundary:

- high common-mode share means stronger common movement;
- it does not establish common cause;
- it does not establish Crowding.

### 7.4 Leader-lag map

For a leader candidate \(i\) and peer \(j\), estimate timing relationships rather than infer them from a picture.

Candidate tools:

- lagged correlation;
- Local Projection;
- VAR/IRF where justified.

Boundary:

\[
\text{Lead-lag}
\neq
\text{Causal Transmission}
\]

## 8. Flow and feedback diagnostics

### 8.1 Signed flow

The engine already has model-internal flow.

For real data the candidate observable is OFI/signed flow.

Question:

\[
F_t
\rightarrow
R_t?
\]

### 8.2 Return-flow response

Feedback requires the reverse direction:

\[
R_t
\rightarrow
F_{t+h}?
\]

A trend-driven move should show stronger positive return-to-future-flow response than a pure one-shot information repricing.

### 8.3 Feedback is not one score

Do not create a universal “reflexivity = 0.73” indicator.

For Case 01, report:

- initial return;
- later trend-flow share;
- whether feedback accelerates or decays;
- loop gain under the specified simulator configuration;
- time horizon.

---

## 9. Liquidity diagnostics

Case 01 is primarily about synchronization, but liquidity can make two identical flows look dramatically different.

Track:

- configured/model depth;
- impact coefficient;
- peak impact;
- transient decay;
- recovery time.

A common-flow scenario should become more extreme when depth falls.

That is useful because:

\[
\text{large move}
\]

does not imply:

\[
\text{large information revision}
\]

when liquidity is weak.

## 10. Expectations layer vs price-formation layer

A central research distinction for Case 01 is:

\[
\boxed{
\text{Economic Expectations}
\neq
\text{Price Formation}
}
\]

Economic expectations ask:

- what changed in expected sales/demand?
- what changed in price/mix?
- what changed in margin or operating leverage?
- what changed in required investment?
- what changed in capacity/supply conditions?

Price formation asks:

- who traded?
- what was the signed flow?
- what was depth?
- what was impact?
- did feedback amplify the move?
- did the move propagate to peers?

The same economic information can create different price paths under different market structures.

The same price path can also arise from different economic information.

That ambiguity is exactly why the case needs competing mechanisms.

## 11. TRQuant momentum research contribution

Existing TRQuant factor work found that one 20-day relative-strength formulation showed materially stronger evidence at a short 5-day horizon than at 20 or 60 days in the studied 2022–2025 sample.

This does not prove a permanent law.

But it gives Case 01 an important research design rule:

> Path persistence must be measured at multiple horizons rather than assumed from a strong current trend.

Therefore Case 01 dynamics fingerprints should include at least:

- immediate horizon;
- short persistence horizon;
- medium decay horizon.

A useful initial simulation mapping is:

- \(H_0\): event/impact window;
- \(H_1\): post-event short persistence;
- \(H_2\): decay/recovery window.

The exact clock time is a simulator parameter, not a claim that simulated seconds equal trading days.

## 12. Expectations gap and “already priced in”

TRQuant investment-practice work and *Expectations Investing* imply a crucial distinction.

A strong semiconductor business trend is not automatically an attractive new investment.

The relevant question is:

\[
\boxed{
\text{What is already embedded in price?}
}
\]

For the later real-data version of Case 01, the evidence panel should separate:

- **Thesis confidence** — is the economic story credible?
- **Market consensus** — how broadly is the story already understood?
- **Price-implied expectation** — what operating assumptions appear embedded?
- **Risk/reward** — how much additional favorable revision is still needed?

The simulator cannot estimate those quantities from animation.

It can only show why they matter.

## 14. Evidence escalation ladder

The Case 01 real-data workflow should escalate evidence in this order.

### Level 0 — Observation

- synchronized returns;
- unusual breadth;
- unusual volume.

### Level 1 — Statistical structure

- market residual;
- theme residual;
- common mode;
- dispersion.

### Level 2 — Temporal structure

- who moved first;
- how quickly peers responded;
- whether the move persisted or reverted.

### Level 3 — Mechanism observables

- earnings/guidance/revisions;
- ETF/common flow;
- signed flow/OFI;
- depth/spread;
- holdings/exposure where available.

### Level 4 — Economic channel

- customer demand;
- supply constraints;
- capex;
- pricing/mix;
- operating leverage;
- policy/industry structure.

### Level 5 — Decision relevance

- persistent repricing?
- transient flow?
- feedback continuation?
- liquidity fragility?
- already priced in?
- which stock has the strongest stock-specific residual worth deeper research?

Do not jump from Level 0 directly to Level 5.

The project copy of *Quantitative Trading* reinforces several rules already present in TRQuant governance.

- point-in-time availability;
- survivorship bias;
- look-ahead;
- data snooping;

- transaction costs;
- changing market environments.

For Case 01 specifically:

- use historical dynamic universe membership where required;
- do not define theme members using future knowledge without versioning;
- timestamp information availability;
- separate event timestamp from retrieval timestamp;
- preserve original evidence;
- evaluate robustness across periods, not only a single AI bull phase;
- never call a descriptive association causal without sufficient identification.

## 19. The first engine slice: deeper implementation requirements

The next code checkpoint remains bounded to:

\[
\boxed{
\text{Baseline}
\leftrightarrow
\text{Theme Information}
\leftrightarrow
\text{Common Theme Flow}
}
\]

But it must now satisfy these deeper research requirements.

### 19.1 Theme information is not a generic price bump

Represent it as a revision in a latent semiconductor expectation state.

For v1, a single scalar \(\Delta E^{semi}\) is acceptable if it is explicitly named as a compressed expectation revision.

The engine maps that revision to theme members' reference anchors.

### 19.2 Common flow must not change the reference anchor

Persistent theme flow changes orders, not latent economics.

### 19.3 The two runs must share everything else

- seed;
- agents;
- initial inventory;
- liquidity;
- network;
- noise;
- baseline prices;
- simulation duration;
- event time.

### 19.4 Attribution must separate initiator and amplifier

Do not print:

> information 40%, flow 30%, feedback 20%

if “flow” is simply the downstream response to the information shock.

Instead expose at least:

- initiating intervention;
- direct reference-anchor contribution;
- direct exogenous flow contribution;
- endogenous participant-flow response;
- feedback contribution;
- network contribution;
- residual.

### 19.5 Recovery is a core discriminator

After the intervention ends:

- measure how much of the move persists;
- measure how quickly it decays;
- measure whether the theme remains synchronized;
- measure whether trend flow continues.

## 20. First quantitative acceptance tests

The first engine slice should pass deterministic tests such as:

### T1 — identical baseline

With the same seed and no intervention:

\[
Run_A = Run_B
\]

within numerical tolerance.

### T2 — isolated information intervention

Theme information run changes theme reference anchors.

Common-flow run does not.

### T3 — isolated flow intervention

Common-flow run creates exogenous theme flow.

Information run does not inject the same exogenous flow.

### T4 — accounting reconciliation

For every sampled asset step:

\[
r_t
=
r_t^{reference}
+
r_t^{exogenous\ flow}
+
r_t^{endogenous\ response}
+
r_t^{network}
+
r_t^{residual}
\]

within declared tolerance and accounting convention.

### T5 — deterministic replay

Same:

- commit;
- case version;
- seed;
- parameters;
- event stream

must reproduce the sampled path.

### T6 — counterfactual discrimination

At least one frozen dynamics fingerprint must differ between A and B in the expected direction.

Candidate initial fingerprints:

- permanent/reference component;
- post-intervention recovery;
- participant mix;
- exogenous-flow share.

If no discriminating fingerprint exists, the experiment is not informative enough.
